# SAWTIX — استوديو صوتي عربي من FINIX

توليد تعليق صوتي عربي (سعودي/خليجي) بتوقيت دقيق ونبرات متحكَّم بها، مع تشكيل عربي محلي،
مراجعة لغوية، تحويل من الفصحى إلى اللهجة، وتصدير MP3 + SRT.

---

## 1. المتطلبات

| المكوّن | الإصدار | ملاحظة |
|---|---|---|
| Node.js | **18.17+** (مُختبر على 20) | لا يحتاج خطوة بناء — ESM خالص |
| Python | **3.10+** (مُختبر على 3.13) | محرك الصوت والمشكّل يعملان عبره |
| ffmpeg | يُثبَّت تلقائياً | عبر حزمة `ffmpeg-static` |
| إنترنت | مطلوب وقت التوليد | محرك الصوت سحابي (Microsoft Read Aloud) |

> بدون `edge-tts` **لا يمكن توليد أي صوت**. بدون `text2tashkeel` يعمل الاستوديو
> بوضع «قاموس اللهجة فقط» (تدهور مقبول لكن بلا تشكيل آلي).

## 2. التثبيت (٣ أوامر)

```bash
npm install          # حزم Node + ffmpeg
npm run setup        # ينشئ بيئة .venv ويثبّت edge-tts + المشكّل
npm run doctor       # فحص البيئة قبل التشغيل
```

أو دفعة واحدة:

```bash
npm run setup
```

> `npm run setup` ينشئ `.venv` داخل المشروع (والخادم يكتشفه تلقائياً)، فيتجنّب
> قيد `externally-managed-environment` في لينكس الحديث و macOS. لاستخدام
> بايثون آخر اضبط `PYTHON_BIN` في `.env`.

ثم:

```bash
npm start            # http://localhost:3000
```

### ويندوز
إن لم يكن `python3` معرّفاً، أضف إلى `.env`:

```
PYTHON_BIN=py
```

## 3. متغيرات البيئة

انسخ `.env.example` إلى `.env` وعدّل ما تحتاجه:

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `3000` | منفذ الخادم |
| `PYTHON_BIN` | `python3` (أو `python` على ويندوز) | مفسّر بايثون |
| `TTS_CONCURRENCY` | `4` | عدد الطلبات المتوازية لمحرك الصوت |
| `TTS_TIMEOUT_MS` | `240000` | مهلة عملية التوليد الواحدة |
| `CACHE_TTL_DAYS` | `14` | عمر كاش الصوت المُولَّد قبل الحذف |
| `OUT_RETENTION_DAYS` | `7` | عمر ملفات التوليد في `out/` قبل الحذف التلقائي |
| `QUEUE_CONCURRENCY` | `2` | عدد مهام التوليد المتوازية في الطابور |
| `QUEUE_MAX_JOBS` | `80` | أقصى عدد مهام محفوظة في الذاكرة |
| `APP_USER` | `admin` | اسم مستخدم الحماية (عند النشر) |
| `APP_PASSWORD` | فارغ (مفتوح) | كلمة مرور الحماية — إلزامية قبل النشر العام |

## 4. خط الإنتاج (ما يحدث فعلياً عند التوليد)

```
نص → مدير الاستوديو (نوع/جمهور/نبرة/صوت/نمط/نطق/إبراز)
   → تطبيع لغوي (كل جملة بلغتها) → مراجعة لغوية → خطة أداء لكل جملة (نية/إبراز/وقفات)
   → تشكيل هجين (نموذج محلي + قاموس سعودي) → فصل العربية عن الإنجليزية
   → توليد كل وحدة بصوتها (مع كاش) → قصّ صمت الأطراف → قياس المدة → مطابقة المدة إن طُلب
   → تركيب على خط زمني → تسوية مستوى → MP3 نهائي + SRT + MP3 لكل مقطع
```

| المرحلة | الملف |
|---|---|
| فهم النص واختيار الصوت والأداء | `lib/director.mjs` |
| التطبيع والأرقام والتقسيم | `lib/normalize.mjs` |
| فهم النية وخطة الإلقاء | `lib/intent.mjs` |
| التشكيل وقاموس النطق | `lib/tashkeel.mjs` + `lib/lexicon.mjs` |
| المراجعة والتحويل للهجة | `lib/qa.mjs` |
| المحرك السحابي | `lib/tts.mjs` + `py/tts.py` |
| حساب التوقيت | `lib/timing.mjs` |
| التركيب والتصدير | `lib/render.mjs` |
| تشغيل بايثون والأخطاء | `lib/python.mjs` |

### مدير الاستوديو التلقائي (`lib/director.mjs`)

طبقة تفهم النص قبل توليده، وتوجّه التنفيذ من المحتوى وحده:

| المخرج | أمثلة |
|---|---|
| نوع المحتوى | إعلان، شرح، خبر، قصة، كوميديا، تحفيز، وثائقي، مراجعة، محتوى اجتماعي |
| الجمهور والتوتر | أطفال/عائلات، نسائي، مهنيون، شباب — مع درجة رسمية وطاقة وحميمية وإلحاح |
| الصوت والنمط والشدة | صوت خليجي مناسب للنوع والجمهور، نمط أداء (طبيعي/حماسي/هادئ...) وشدة 1–5 |
| خطة النطق | اختصارات تُنطق عربياً (`KPI` ← «كِي بِي آي»)، أخطاء إملائية تُصحَّح، أرقام تُحوَّل، كلمات ملتبسة تُكشف، وكلمات أجنبية مجهولة تُقترح للقاموس |
| خطة الأداء | دور كل جملة (افتتاحية/جسم/خاتمة) والكلمات التي تُبرَز بتمهّل وطبقة أعلى |

**قواعد الأولوية:** أي اختيار صريح من المستخدم (`voice` أو `style` أو `intensity` أو `intent`) يتقدّم على اقتراح المدير. إيقافه بـ `"director": "off"` في `settings`.

## 5. نقاط الـ API

| المسار | الوظيفة |
|---|---|
| `GET /api/health` | فحص البيئة (200 سليم / 503 ناقص) — بايثون، محرك الصوت، المشكّل، ffmpeg |
| `GET /api/config` | الأصوات، الأنماط، النيات، حالة المحركات، إحصاءات القاموس |
| `POST /api/analyze` | مراجعة + خطة إلقاء + **موجز مدير الاستوديو** + تقدير مدة (بلا توليد) |
| `POST /api/director` | تحليل نص خام وحده: نوع، جمهور، صوت، نمط، خطة نطق وأداء |
| `POST /api/preview` | معاينة مقطع واحد MP3 |
| `POST /api/jobs` | **إنشاء مهمة توليد في الطابور** (يعود فوراً بـ `jobId`) |
| `GET /api/jobs/:id` | حالة المهمة وتقدّمها الحقيقي |
| `GET /api/jobs/:id/events` | بثّ التقدّم المباشر (SSE) |
| `POST /api/jobs/:id/cancel` | إلغاء المهمة (فوراً في الانتظار / عند أول نقطة آمنة قيد التشغيل) |
| `GET /api/jobs` | سجل المهام + إحصاءات الطابور |
| `POST /api/render` | توليد متزامن (لأدوات curl والاختبار فقط) |
| `POST /api/spoken` | النص كما سيُرسل للمحرك (تشكيل + قاموس) |
| `POST /api/review` | مراجعة لغوية فقط |
| `POST /api/dialectize` | تحويل فصحى → سعودي |

مثال:

```bash
curl -s localhost:3000/api/render -H 'content-type: application/json' -d '{
  "voice": "ar-SA-HamedNeural",
  "settings": { "diacritics": "smart", "timingMode": "exact" },
  "segments": [{ "text": "هلا بك، اليوم نتكلم عن الذكاء الاصطناعي.", "target": 4 }]
}'
```

## 6. الطابور والتقدّم

كل توليد يُنفَّذ **كمهمة** في طابور محدود التزامن:

```
POST /api/jobs  →  202 { id, state: "queued", queuePosition }
        ↓
GET /api/jobs/:id  (كل ٦٠٠ مللي من الواجهة، أو SSE من /events)
        ↓
مراحل التقدّم الحقيقية:
prepare (3%) → synth (6–64%، بعدد الوحدات) → timing (68–74%) → segments (75–92%) → final (94–100%)
```

- **الإلغاء**: في الانتظار يُلغى فوراً؛ وقيد التشغيل يتوقف عند أول نقطة تحقّق (بين الوحدات والمراحل).
- **السجل**: كل مهمة تُحفظ في `out/<jobId>/job.json` وتظهر في «سجل المهام» بالواجهة مع روابط MP3/SRT حتى بعد إعادة التشغيل.
- **التزامن**: افتراضياً مهمتان معاً (`QUEUE_CONCURRENCY`) حتى لا يُغرق مزوّد الصوت.

```bash
# مثال: إنشاء مهمة ومتابعتها
JOB=$(curl -s -X POST localhost:3000/api/jobs -H 'content-type: application/json' \
  -d '{"segments":[{"text":"هلا بك، هذا اختبار الطابور.","target":3}],"settings":{"timingMode":"exact"}}' \
  | python3 -c 'import json,sys;print(json.load(sys.stdin)["id"])')
curl -s localhost:3000/api/jobs/$JOB | python3 -m json.tool
curl -s -X POST localhost:3000/api/jobs/$JOB/cancel     # إلغاء
```

## 8. ملاحظات تشغيلية

- **الصمت**: كل وحدة من المحرك تعود بذيل صمت طويل، فيُقصّ تلقائياً (بهامش ٢٠/٦٠ مللي)
  قبل القياس والتركيب — وإلا امتلأت «الثواني المستهدفة» بصمت بدل كلام.
- **ملف `.env`**: يُقرأ تلقائياً عند الإقلاع (المتغيرات المضبوطة في البيئة لها الأولوية).
- **الملفات**: كل توليد في مجلد داخل `out/`، ويُحذف تلقائياً بعد `OUT_RETENTION_DAYS`.
- **الكاش**: الوحدة الصوتية المتطابقة (نص + صوت + سرعة + طبقة + مستوى) لا تُعاد من الشبكة.
- **الخصوصية**: محلياً الوصول مفتوح. قبل أي نشر عام اضبط `APP_PASSWORD` (حماية Basic) — وإلا صار المحرك متاحاً للجميع.
- **شروط الاستخدام**: `edge-tts` يستخدم خدمة القراءة الصوتية غير الرسمية من مايكروسوفت؛
  للاستخدام التجاري الكثيف يُنصح بمحرك رسمي (Azure Speech) عبر `lib/tts.mjs`.

## 9. النشر على رابط دائم (SAWTIX)

الاستوديو ليس موقعاً ثابتاً: يحتاج Node + Python (`edge-tts` والمشكّل) + ffmpeg.
لذلك **Freebuff Sites لا يشغّله** (يستضيف ملفات ثابتة وWorkers فقط)، والنشر يحتاج حاوية Docker.

### الخيار أ — Render (خطة Free) عبر GitHub

1. ارفع المشروع إلى مستودع GitHub (خاص أو عام).
2. في Render: **New → Blueprint** واختر المستودع — ملف `render.yaml` جاهز ويبني `Dockerfile` تلقائياً.
3. عند أول نشر اضبط `APP_PASSWORD` في **Environment** (وليس في الكود).
4. الرابط سيكون بالشكل `https://sawtix.onrender.com` (يتغير إن كان الاسم محجوزاً).

حدود الخطة المجانية: 512MB وذاكرة مشتركة، ونوم بعد خمول (إقلاع بارد). إن لم يكفِ التشكيل الذكي للذاكرة يعمل النظام تلقائياً بوضع قاموس اللهجة. للاستخدام اليومي المريح: خطة 1GB.

### الخيار ب — Hugging Face Spaces (Docker)

> منذ 2026 صارت مساحات Docker/Gradio على Hugging Face تتطلب خطة مدفوعة (PRO ≈ 9$/شهر للفرد)؛ المساحات الثابتة فقط مجانية. إن كانت لديك PRO فهذا أبسط خيار: مساحة خاصة + 16GB RAM.

1. أنشئ توكن **Write** من Settings → Access Tokens.
2. أضفه في هذا المشروع باسم `HF_TOKEN` ضمن **Settings → Project settings → Secrets** (لا تلصقه في المحادثة).
3. نفّذ:

```bash
HF_TOKEN=... HF_SPACE=sawtix npm run deploy:hf
```

السكربت ينشئ المساحة، يرفع الحزمة، ويطبع الرابطين:
`https://huggingface.co/spaces/<user>/sawtix` و`https://<user>-sawtix.hf.space`.

### الخيار ج — أي VPS بخدمة Docker (~5$/شهر)

```bash
git clone <repo> && cd sawtix
docker build -t sawtix .
docker run -d --restart unless-stopped -p 80:7860 -e APP_PASSWORD=... --name sawtix sawtix
```

- التطبيق يستمع على `0.0.0.0` ومنفذ `PORT`، ويصلح خلف أي Proxy (Caddy/Nginx) مع HTTPS.
- الذاكرة المقترحة: 1GB أو أكثر (نموذج التشكيل + ffmpeg).
- التخزين مؤقت: `out/` يُفقد عند إعادة الإنشاء، والكاش يُعاد بناؤه.

### فحص محلي لصورة الإنتاج

```bash
docker build -t sawtix .
docker run --rm -p 7860:7860 -e APP_PASSWORD=change-me sawtix
# http://localhost:7860
```

### ما لم يُنفَّذ بعد (P3)
- حدود استخدام وجلسات متعددة المستخدمين و`helmet` ومراقبة.
- تصدير WAV/CSV، ومعايرة EBU R128 بتمريرتين.
- محرك احتياطي رسمي، واستنساخ صوت.
- حلقة ASR لقياس النطق موضوعياً (الجولة ٣ في خطة الجودة).
